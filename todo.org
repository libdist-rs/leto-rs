   and registers Hash::ser_and_hash(&Vec<Tx>) → send_ts.  The server's

   4. Have the Stressor watch the server's commit channel instead of
      Confirmation roundtrip — but requires a new subscribe protocol.

   reading.  Option 1 is the simplest correct fix.

* Design: data-chain-valid refactor                              :Zeus:Refactor:Correctness:

  Replace the lazy O(H) =data_chain_valid= with eager O(1) admission
  invariants enforced at insert time.

** Invariant (new)
   Every block in =data_block_store= has been confirmed:
   1. Signature valid under the eleader of its epoch.
   2. =parent_hash= links to another block already in the store
      (or to =dataGenesis= for height 1).
   3. No equivocation: no other store entry has the same
      =parent_hash= (one child per parent).

   Consequence: chain-membership of any stored block is structural,
   not computed. =data_chain_valid(D)= becomes a store-membership
   lookup -- O(1).

** State changes in DataChainState
   - Keep: =head_hash=, =head_height=, =data_block_store=.
   - Add: =child_of: FnvHashMap<DataBlockHash, DataBlockHash>=
     -- parent_hash → child_hash. Built on each successful admit.
     Enables O(1) "is the next height already pending?" and powers
     equivocation rejection.
   - Add (optional, later): =pruning_floor: u64= for store GC below
     the Zeus-committed watermark. Out of scope for this refactor.

** Admission rules (new on_data_propose path)
   On admit attempt for incoming block D:
   1. =data_block_valid(D, e_cur)= -- signature, epoch, height fields.
      Reject on failure (existing).
   2. *Equivocation check*: if =child_of.contains_key(&D.parent_hash)=
      and =child_of[D.parent_hash] != H(D)=, the eleader has signed
      two distinct children of the same parent. Reject with
      =warn!("equivocation: …")=. (Full blame logic stays deferred.)
   3. Position D:
      a. =D.parent_hash == head_hash=  →  *fast path*: insert D,
         set =head_hash = H(D)=, =head_height += 1=, populate
         =child_of[old_head_hash] = H(D)=. *O(1).*
      b. =D.parent_hash != head_hash= AND parent is in store  →
         out-of-order extension of a non-head block (catch-up
         filling forward). Insert D, populate =child_of=. Do NOT
         advance head. Then *drain*: while =child_of[head_hash]=
         exists, advance head one step. *O(k)* where k = bridged
         depth.
      c. Parent not in store  →  park reception, emit =DataRequest=
         for =D.parent_hash=. (Existing catch-up flow; trigger via
         the same =pendingAttestations= idiom or a parallel
         =pendingDataBlocks=.)

** data_chain_valid (new)
   #+begin_src rust
   pub fn data_chain_valid(&self, hash: &DataBlockHash<Tx>) -> bool {
       // O(1): membership in the validated store IS chain-validity
       // by the admission invariant.
       self.data_block_store.contains_key(hash)
   }
   #+end_src

   This replaces the entire backward walk. The =attestation_valid=
   call site (=phases/attestation.rs=) inherits the speedup
   automatically. The =Parked(hash)= branch of =AttestationValidity=
   is unchanged -- if the pinned block is not in the store, we still
   park and request.

** Correctness sketch
   *Induction.* Genesis block satisfies invariants trivially (height 0,
   no parent). Inductive step: when D is admitted via case (a), its
   parent (head) is in the store by induction; the equivocation check
   ensures =child_of= remains injective; the parent_hash linkage is
   verified by direct comparison =D.parent_hash == head_hash=. The
   store now contains D, and the chain head → ... → genesis is
   well-formed. Case (b) is the same induction applied to a non-head
   ancestor; head doesn't advance unless the drain succeeds. Case (c)
   does not insert anything until parent arrives.

   *Equivocation.* A Byzantine eleader signing two distinct children
   D₁, D₂ of the same parent is caught at step 2 of admission: the
   second arrival sees =child_of[parent_hash]= already set, rejects.
   The first arrival -- whichever wins the race -- is admitted; the
   second is dropped (logged). This matches the spec's
   "no equivocation admitted on the locally-extended data prefix"
   without invoking blame logic.

   *Out-of-order delivery.* The catch-up flow (=on_data_response=
   inserting a missing intermediate block) lands in case (b). Drain
   advances head as the bridge completes.

** What this refactor does NOT change
   - Wire format (=DataBlock=, =Attestation= shapes unchanged).
   - =attestation_valid= tri-state semantics
     (=Valid= / =Invalid= / =Parked=).
   - =commit_lock= population or the prefix-commit projection.
   - =pendingAttestations= replay path.
   - The =data_block_valid(D, e_cur)= signature -- catch-up still
     passes =D.epoch= as =e_cur=.
   - The deferred view-change path or any blame logic.

** Risk
   - The walk currently exists; some code may implicitly depend on
     its side-effects (e.g. propagating a missing-ancestor signal up
     to trigger =DataRequest=). The refactor must preserve that:
     case (c) is explicitly the parked-parent branch.
   - Pruning is NOT in scope; the store grows. Add a separate task to
     GC below the Zeus-committed watermark once this lands and is
     stable.

** Refactor steps (in dependency order)
   1. Add =child_of= to =DataChainState=; populate on existing insert
      sites (no behavior change yet).
   2. Add equivocation rejection at the admit site, gated by
      =child_of= collision. Smoke test: confirm no rejections under
      honest eleader.
   3. Add the three-case admission logic in =on_data_propose=.
      Migrate fast-path callers to case (a). Keep the old
      =data_chain_valid= temporarily as a parallel check (assert old
      and new agree).
   4. Once parity confirmed across a stress run, delete the old
      walk-based =data_chain_valid= body and replace with the O(1)
      store-membership lookup. Remove parallel-check.
   5. Re-profile. Confirm 35% CPU freed and sig-round latency no
      longer grows with H.

** Case (c) handling: request/response
   *Decision (user, 2026-05-18).* Handle missing-parent via the
   existing =MsgDataRequest= / =MsgDataResponse= machinery. The
   responding node must serve from its own validated
   =data_block_store= -- no fabrication, no relay-from-elsewhere.

   *Mechanics.*
   - On =on_data_propose= reaching case (c): park D in a new
     =pendingDataBlocks: FnvHashMap<DataBlockHash, Vec<DataBlock>>=
     keyed by =D.parent_hash=. Broadcast
     =ZeusMsg::DataRequest { target_hash: D.parent_hash, source: self.my_id }=.
     Capture the returned =CancelHandler=s into =round_state.add_handlers=
     -- see [[file:~/.claude/projects/-Users-hermitsage-Github-leto-rs/memory/feedback_cancel_handlers_first.md][feedback_cancel_handlers_first]].
   - =on_data_request= is unchanged: serves =DataResponse= only if
     the requested hash is in the local =data_block_store= (which
     under the new invariant means the responder has validated it).
   - =on_data_response= becomes an admit call: re-enters the three-
     case logic. If the response's parent is also missing, this
     cascades into another =DataRequest=, bounded by the depth from
     the response back to the nearest in-store ancestor.
   - On successful admission of a block D' (any case), drain
     =pendingDataBlocks[H(D')]= and re-admit each parked child. The
     drain naturally interleaves with the case-(b) head-advance
     drain so a long out-of-order chain unwinds in one pass.

   *Symmetry.* This mirrors =pendingAttestations= exactly. Same park-
   then-replay idiom, same wire messages -- only the index type
   differs (data-block-hash vs. attestation's data-block-hash).
   Consider whether to unify the two maps as a follow-up; not in
   scope for this refactor.

    *Cause.* In =LetoBroadcast= the stressor broadcasts every =NewBatch=
    to all =n= nodes (=stresser.rs:257=). Every node's client listener
    pushes those txs into its own batcher channel (=core.rs:239-244=).
    Only the *proposing* leader's =Txpool::make_batch= removes txs (via
    =pop_front=, =tx_pool.rs:106-124=). The other =n-1= pools retain the
    same txs. After leader rotation each of the =n-1= other nodes
    eventually leads and re-proposes the same txs. Over =n= rounds each
    tx is committed ≈ =n= times.

    *Dead code that should have caught it.* =BatcherConsensusMsg::Commit
    { batch }= (=rr_batcher.rs:17=) is defined with a working
    =clear_batch= handler (=:135-138=) -- but the variant is *never
    constructed anywhere*. =OptimisticClear= (the only signal sent
    after a propose) is a no-op (=:139-142=).

*** Design: nonce-keyed state machine
    Each tx carries =(client_id, nonce)= where =nonce= is monotonically
    increasing per client. The stresser already does this: =tag= in
    =ExtraData= is the per-client tx counter (=stresser.rs:234=) and
    =source= is the client id. They are currently buried in a
    bincode-serialized =extra: Vec<u8>= and only exposed under
    =cfg(feature = "benchmark")=; this refactor lifts them to top-level
    typed fields visible to the always-on trait.

    *Replicated state, per node:*
    =high_committed_nonce: HashMap<ClientId, Nonce>= -- the maximum
    nonce committed on the canonical chain for each client. Size
    O(#clients), not O(#committed txs).

    *Per-tx state machine:*

    | State       | Storage                                 | Eligible for batch? |
    |-------------+-----------------------------------------+---------------------|
    | =Unknown=     | (no storage)                            | n/a                 |
    | =Mineable=    | =BTreeMap<(ClientId, Nonce), (Tx, size)>= | yes                 |
    | =InFlight(r)= | =HashMap<(c, n), entry>= + by_round idx   | no                  |
    | =Replayed=    | (no storage; rejected at add_tx)        | no                  |

    The Committed state from the prior LRU/Bloom design is *gone*:
    its purpose (rejecting late-arriving committed txs) collapses to
    a u64-compare against =high_committed_nonce[client]=.

    *Transitions:*

    #+begin_example
                              ┌───────────┐
                              │  Unknown  │
                              └─────┬─────┘
                          add_tx()  │  admit_proposal(batch, r)
                          (client)  │  -- both gated by:
                          if n >    │     n > high_committed_nonce[c]
                          hi_committed[c]
                                    ▼
                          ┌──────────────────┐
                ┌──────►  │     Mineable     │ ◄──── rollback(r) ──────┐
                │         │   keyed (c, n)   │                          │
                │         └────────┬─────────┘                          │
                │      admit_proposal()  /  make_batch()                │
                │                  │   (both promote, tag with r)       │
                │                  ▼                                    │
                │         ┌──────────────────┐                          │
                │         │   InFlight(r)    │ ◄── idempotent ──────────┤
                │         │  keyed (c, n)    │     re-admit             │
                │         └────────┬─────────┘                          │
                │     ┌────────────┼──────────┐                         │
                │     │ commit()   │          │ rollback(r)             │
                │     │ hi[c] :=   │          │ chain-switch            │
                │     │ max(.,n)   │          │                         │
                │     ▼            │          ▼                         │
                │  ┌───────────────┴┐                                   │
                │  │  GC: drop any  │                                   │
                │  │  entries with  │ ───────────────────────────────── ┘
                │  │  n ≤ hi[c]     │     (subsumed orphans dropped,
                │  └────────────────┘      others returned to Mineable)
                │

*** Race traces (all close to no-ops or correct moves)

    *Trace 1 -- common case (client copy arrives first):*
    #+begin_example
    t0  client broadcasts T=(c, n=5)
    t1  X gets T via client                 → add_tx: 5>hi[c]=0 → Mineable[(c,5)]
    t2  X gets P={T} via consensus          → admit_proposal:
                                              (c,5) in Mineable → InFlight(r)
    t3  P commits at round r                → commit:
                                              hi[c] := 5; remove (c,5)
    #+end_example

    *Trace 2 -- proposal arrives before client (LAN race):*
    #+begin_example
    t0  client broadcasts T=(c, 5)
    t1  X gets P={T} via consensus first    → admit_proposal:
                                              5>hi[c]=0; not in any bucket
                                              → InFlight((c,5), r) direct
    t2  X gets T via client                 → add_tx: 5>hi[c]; (c,5)
                                              in InFlight ⇒ NO-OP   ✓
    #+end_example

    *Trace 3 -- late client after commit (RTO; was the hard case):*
    #+begin_example
    t0  X gets P={T=(c,5)}                  → InFlight((c,5), r)
    t1  P commits                            → hi[c] := 5; remove (c,5)
    t2  X finally gets T via client (RTO)   → add_tx: 5 ≤ hi[c]=5 ⇒ DROPPED ✓
    #+end_example

    *Trace 4 -- chain switch orphans round r:*
    #+begin_example
    t0  X promoted (c,5) at round r         → InFlight((c,5), r)
    t1  commit.rs:178-187 fires             → rollback({r}):
                                              5 > hi[c] (still 0) →
                                              (c,5) → Mineable
    #+end_example

    *Trace 5 -- view change commits a different proposal at round r:*
    #+begin_example
    t0  X promoted (c,5) at r via P1        → InFlight((c,5), r)
    t1  canonical chain commits P2 ≠ P1 at r,
        where P2 contains (c,7)             → commit({(c,7)}, r):
                                              hi[c] := 7;
                                              GC sweep: (c,5) ≤ 7
                                              → drop (c,5)  ✓
    #+end_example

    *Trace 6 -- Byzantine client replays old nonce:*
    #+begin_example
    t0  hi[c] = 10 already
    t1  Byzantine T'=(c, 3) arrives         → add_tx: 3 ≤ 10 ⇒ DROPPED  ✓
    #+end_example

    *Trace 7 -- Byzantine leader proposes already-committed nonce:*
    #+begin_example
    hi[c] = 10 at honest X
    Byzantine leader proposes P={(c,3)}
    X.admit_proposal: 3 ≤ 10 → skip this tx (or reject the whole
                                proposal -- see "Byzantine proposal
                                policy" below).
    #+end_example

    *Trace 8 -- own loopback at proposer L:*
    #+begin_example
    t0  L make_batch(r)                     → pops from Mineable,
                                              moves to InFlight((c,n), r)
    t1  L handle_proposal (loopback)        → admit_proposal:
                                              (c,n) in InFlight ⇒ continue ✓
    #+end_example

    *Trace 9 -- equivocation (same (c,n), different payload):*
    #+begin_example
    t0  X gets T_A=(c, 5, payload_A)        → Mineable[(c,5)] = T_A
    t1  X gets T_B=(c, 5, payload_B)        → BTreeMap::insert overwrites
                                              → last-write-wins; system commits
                                              one of them, both have same key.
    #+end_example

    (For a signed-tx scheme, equivocation would be detectable and
    slashable; unsigned txs as today accept last-write-wins. Not in
    scope for this refactor.)

*** State changes in =Txpool=

    Replace the single =linked_hash_map: LinkedHashMap<Hash<Tx>, …>=
    with:

    #+begin_src rust
    pub struct Txpool<Tx> {
        // State: Mineable -- BTreeMap so we can range-scan by client.
        // Insertion-order FIFO is sacrificed; nonce-ordering within
        // a client is preserved (BTreeMap iterates sorted by key).
        mineable: BTreeMap<(ClientId, Nonce), (Tx, /*size*/ usize)>,
        mineable_bytes: usize,

        // State: InFlight by (client, nonce); secondary index by round.
        inflight: HashMap<(ClientId, Nonce), InflightEntry<Tx>>,
        inflight_by_round: HashMap<Round, FnvHashSet<(ClientId, Nonce)>>,

        // Replicated state -- O(#clients).
        high_committed_nonce: HashMap<ClientId, Nonce>,

        batch_size: usize,
        timer: Interval,
    }

    struct InflightEntry<Tx> {
        tx: Tx,
        size: usize,
        round: Round,
    }
    #+end_src

    Note: FIFO-by-arrival ordering of =mineable= is dropped. Batches
    now contain txs in =(client, nonce)= sort order. This is *better*
    for latency fairness across clients (round-robin-ish) and gives
    deterministic batch contents.

*** Operations (each amortized O(1) per tx)

    #+begin_src rust
    impl<Tx: Transaction> Txpool<Tx> {
        pub fn add_tx(&mut self, tx: Tx, size: usize) {
            let (c, n) = (tx.client_id(), tx.nonce());
            if n <= *self.high_committed_nonce.get(&c).unwrap_or(&0) {
                return; // replay / late RTO / Byzantine
            }
            if self.inflight.contains_key(&(c, n)) {
                return; // proposal-direct race already inserted
            }
            // BTreeMap::insert overwrites; in honest case this is idempotent;
            // in equivocation case it's last-write-wins (see Trace 9).
            if let Some(prev) = self.mineable.insert((c, n), (tx, size)) {
                self.mineable_bytes -= prev.1; // adjust for overwrite
            }
            self.mineable_bytes += size;
        }

        pub fn admit_proposal(&mut self, batch: &Batch<Tx>, round: Round) {
            let by_round = self.inflight_by_round.entry(round).or_default();
            for tx in &batch.payload {
                let (c, n) = (tx.client_id(), tx.nonce());
                if n <= *self.high_committed_nonce.get(&c).unwrap_or(&0) { continue; }
                if self.inflight.contains_key(&(c, n))                   { continue; }
                let size = if let Some((_, sz)) = self.mineable.remove(&(c, n)) {
                    self.mineable_bytes -= sz; sz
                } else {
                    bincode::serialized_size(tx).unwrap_or(0) as usize
                };
                self.inflight.insert(
                    (c, n),
                    InflightEntry { tx: tx.clone(), size, round },
                );
                by_round.insert((c, n));
            }
        }

        pub fn make_batch(&mut self, round: Round) -> Batch<Tx> {
            let mut payload = Vec::new();
            let mut batch_bytes = 0;
            let by_round = self.inflight_by_round.entry(round).or_default();
            // BTreeMap iteration is sorted by (client, nonce). Pop the
            // smallest keys until batch_size satisfied.
            while batch_bytes < self.batch_size {
                let key = match self.mineable.keys().next().copied() {
                    Some(k) => k,
                    None => break,
                };
                let (c, n) = key;
                let (tx, size) = self.mineable.remove(&key).unwrap();
                self.mineable_bytes -= size;
                payload.push(tx.clone());
                batch_bytes += size;
                self.inflight.insert((c, n), InflightEntry { tx, size, round });
                by_round.insert((c, n));
            }
            self.reset_timer();
            Batch { payload }
        }

        pub fn commit(&mut self, batch: &Batch<Tx>, round: Round) {
            // 1. Advance high_committed_nonce; remove the committed txs
            //    from both buckets.
            let mut touched: FnvHashSet<ClientId> = FnvHashSet::default();
            for tx in &batch.payload {
                let (c, n) = (tx.client_id(), tx.nonce());
                touched.insert(c);
                if let Some(e) = self.inflight.remove(&(c, n)) {
                    if let Some(set) = self.inflight_by_round.get_mut(&e.round) {
                        set.remove(&(c, n));
                    }
                }
                if let Some((_, sz)) = self.mineable.remove(&(c, n)) {
                    self.mineable_bytes -= sz;
                }
                let cur = self.high_committed_nonce.entry(c).or_insert(0);
                if n > *cur { *cur = n; }
            }
            // 2. GC straggler entries beneath the new high-water marks.
            //    Per client, range-scan mineable -- O(|stale|), not O(|pool|).
            for c in &touched {
                let hi = *self.high_committed_nonce.get(c).unwrap();
                let stale: Vec<_> = self.mineable
                    .range((*c, 0)..=(*c, hi))
                    .map(|(k, _)| *k)
                    .collect();
                for k in stale {
                    if let Some((_, sz)) = self.mineable.remove(&k) {
                        self.mineable_bytes -= sz;
                    }
                }
            }
            // 3. Inflight stragglers are filtered lazily in admit_proposal
            //    and rollback; growth is bounded by commit_len rounds of
            //    in-flight work.
        }

        pub fn rollback(&mut self, rounds: &[Round]) {
            for r in rounds {
                if let Some(set) = self.inflight_by_round.remove(r) {
                    for (c, n) in set {
                        let hi = *self.high_committed_nonce.get(&c).unwrap_or(&0);
                        if n <= hi {
                            // Subsumed orphan: a different proposal at round r
                            // already committed a higher nonce from c.  Drop.
                            self.inflight.remove(&(c, n));
                            continue;
                        }
                        if let Some(e) = self.inflight.remove(&(c, n)) {
                            self.mineable.insert((c, n), (e.tx, e.size));
                            self.mineable_bytes += e.size;
                        }
                    }
                }
            }
        }

        pub fn ready(&self) -> bool { self.mineable_bytes > self.batch_size }
    }
    #+end_src

    *=debug_assert!= invariants:*
    - =mineable= and =inflight= key sets are disjoint.
    - For all =(c, n) in inflight=, =n > high_committed_nonce[c]=
      (after admit_proposal / rollback / commit returns).
    - =inflight_by_round[r] = { (c, n) | inflight[(c,n)].round == r }=.
    - =mineable_bytes = Σ size in mineable=.

*** Byzantine proposal policy (decision needed)

    When =admit_proposal= encounters a stale tx (=n ≤ hi[c]=), two
    policies:

    *(a) Silent skip* (simple): the stale tx is ignored; the rest of
    the batch is admitted normally. The committed batch will still
    contain the stale tx (we don't rewrite proposals), and
    =DP[Throughput]='s payload.len() count will still include it.

    *(b) Reject proposal* (strict): the whole proposal is rejected
    with =warn!("stale nonce from leader: …")=. This requires
    extending =handle_proposal='s validity check
    (=proposal.rs:46-93=) with a per-tx nonce sweep.

    *Recommendation: (a) for v1.* The metric-correctness fix already
    achieves the main goal (n× → 1×); rejecting Byzantine-leader
    proposals is a separate hardening pass. For honest runs, no stale
    nonces ever appear in proposals, so the policy is moot. Leave
    a TODO and the rejection logic for a follow-up.

*** Persistence

    =high_committed_nonce= is replicated state and *must* be derivable
    from the chain. For paper experiments: in-memory only; each
    experiment starts with empty state, clients start at nonce 1.
    Restart-mid-run is out of scope.

    *Future-proofing.* Storing =high_committed_nonce= as a RocksDB
    column family (keyed by ClientId, value Nonce, one tiny write per
    commit) would survive restarts. Add as a follow-up task once
    paper experiments stabilize.

*** Risk / open questions

    - *=Mineable= ordering change* (LinkedHashMap FIFO → BTreeMap
      sorted by (client, nonce)). Per-client FIFO is preserved
      (nonces are monotonic per client). Across clients, the batch
      composition shifts from "oldest-arrival first" to "lowest-client-
      first". This is *better* for fairness but may affect
      latency-by-client measurements -- verify in tests.
    - *Trait promotion blast radius.* =Attestation<Tx>= impl needs
      stubs; verified above. Any other =impl Transaction= will fail
      to compile until updated. Grep is clean -- only =SimpleTx=
      (two copies) and =Attestation<Tx>= implement the trait today.
    - *=ExtraData= wire format change.* =source= and =tag= removed
      from the serialized blob. Backwards incompatibility with any
      saved benchmark traces; not a concern (no such artifact set).
    - *Trait method =get_id= name collision.* =Transaction::get_id=
      currently returns the sample_id (u64). The newly-added
      =Transaction::nonce= returns the per-client nonce. *Do not*
      rename =get_id= even though =nonce= would be a clearer name --
      the existing name has consumer code in =leto/phases/commit.rs:236=
      and elsewhere referencing sample tracking.
